# AGENTS.md

`shoes` is a multi-protocol proxy server in Rust (edition **2024**). Single crate, no workspace.

## Commands

CI gates (run these before claiming done, in this order):

```bash
cargo fmt -- --check      # lint.yml: formatting
cargo clippy -- -D warnings   # lint.yml: warnings are errors
cargo build --verbose     # test.yml
cargo test --verbose      # test.yml
```

- Run one test: `cargo test <name>` — tests are **inline `#[cfg(test)]` modules** inside `src/**`, not a `tests/` dir. There are no integration-test fixtures or external service prerequisites.
- Release profile uses `lto = "fat"` + `strip` — release builds are slow; prefer debug for iteration.

## Crate layout (one crate, three outputs)

`Cargo.toml` `crate-type = ["rlib", "cdylib", "staticlib"]` plus a `[[bin]]`. Same source serves all:

- **Binary** (`src/main.rs`) — the CLI proxy server. Declares its own `mod` list.
- **Library** (`src/lib.rs`) — re-declares the same modules (keep the two `mod` lists in sync when adding a module) for mobile/FFI embedding.
- `#![allow(dead_code)]` is intentional in `lib.rs`: server code looks unused in lib builds but is used by the binary and FFI. Do not "clean up" apparent dead code.

Module boundaries: each protocol is its own dir/file under `src/` (`vmess/`, `vless/`, `reality/`, `shadowsocks/`, `anytls/`, `naiveproxy/`, `snell/`, `tuic_server.rs`, `hysteria2_server.rs`, ...). Config parsing/validation is `src/config/` (`types/`, `validate.rs`, `pem.rs`). Routing in `src/routing/`, proxy chaining in `src/tcp/` + `client_proxy_*`. `src/tun/` is `#[cfg(unix)]` only. `src/ffi/` is gated behind `#[cfg(any(target_os = "android", target_os = "ios", feature = "ffi"))]`.

## Non-obvious CLI facts

`src/main.rs` is the source of truth for CLI flags, and it is **ahead of README/CONFIG.md**. Verified extras not in the docs:

- `-l, --log-file PATH` (repeatable; `-` = stderr)
- `-V, --version`
- `generate-vless-user-id` command (UUID v4)
- With **no config arg**, defaults to loading `config.shoes.yaml`.
- Logging level uses a `RUST_LOG`-style directive (`src/logging.rs::resolve_directives`, reads `RUST_LOG` env). `Cargo.toml` sets `release_max_level_info`, so `debug!`/`trace!` are compiled out in release.

Full YAML config reference lives in `CONFIG.md`; it is thorough but trails the code — trust `src/config/` when they disagree.

## Toolchain quirks

- Crypto backend is **aws-lc-rs** throughout (rustls, quinn, hickory all pinned to the `-aws-lc-rs` feature variants). Do not introduce ring or a second TLS backend.
- Allocator: **jemalloc** (`tikv-jemallocator`) is the global allocator except on msvc/iOS/Android (see `main.rs` cfg + `Cargo.toml` target block).
- musl targets get static CRT via `.cargo/config.toml`.
- Dependency versions are `"*"` — pins live in `Cargo.lock`. Use `--locked` in CI-style builds.

## Mobile / FFI builds

- iOS XCFramework: `bash scripts/build-ios.sh` (needs Xcode + cbindgen; sets `IPHONEOS_DEPLOYMENT_TARGET=16.0`, regenerates `include/shoes.h` via `cbindgen.toml`).
- Android AAR: `bash scripts/build-android.sh` (needs `ANDROID_NDK_HOME`, cargo-ndk, Gradle 8.6+, Java 17). Native libs built with `cargo ndk ... -- build --release --lib`.
- `include/shoes.h` is **auto-generated by cbindgen** — never hand-edit it; change `cbindgen.toml` / the FFI source instead.

## Conventions

- Default branch is `master`; CI (fmt, clippy, test, build, mobile) runs on push/PR to `master`. Releases are tag-driven (`v*`) and created as **drafts**.
- Adding a new protocol module: create the dir under `src/`, then register it in **both** `src/main.rs` and `src/lib.rs`.
